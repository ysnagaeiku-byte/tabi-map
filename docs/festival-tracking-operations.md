# 車両の位置（Traccar Client）運用手順

本祭支援ツールで 1〜3号車の位置を本部の地図に出すための当日の手順です。初回の準備（Cloudflare への配置・秘密値の作成）は [tracking-worker/README.md](../tracking-worker/README.md) を参照してください。

秘密の扱い：
- 設定シート（`tracking-worker/.secrets/production-setup.html`）の QR コード・URL・閲覧キーは秘密です。
- 運転する人には、自分の車両の QR だけを読ませます。
- 写真・チャット・画面共有で広めません。

## 本部版と配布版

| 種類 | できること | 始め方 |
| --- | --- | --- |
| 本部版（全権限） | すべて。時刻表の編集、配布版の発行・取り消しもできる | 設定シート（`tracking-worker/.secrets/production-setup.html`）の「本部版のリンク」を、本部の端末で一度開く |
| 配布版 | 車両の位置・開錠・施錠時刻・EVを見られる。発行時に選んだ制限がかかる | 本部版で発行したリンク・QRを、配布先の端末で開く |

**配布版の制限**：発行のたびに次の3つから選びます。
- 設定画面を開けない
- ピンを保存できない
- EVの可否を編集できない（許可しても、開錠・施錠時刻と黒帯の情報は本部版だけが変えられます）

EVの編集は受信APIでも拒否します。設定画面とピンは、画面上で使えなくする制限です。

**本部版のキーの記憶**：本部版（全権限）と確かめたキーは、端末に別にも記憶します（`fest_hq_key`）。本部の端末で配布版のリンクやキーを開いても「このタブだけ」の表示になり、本部版のキーは上書きされません。キーが消えていたら、開いたときに戻します。
- iPhone・iPad は、Safari とホーム画面のアプリで保存場所が別です。本部の端末は、どちらか一方だけで使ってください（両方で使うなら、両方で本部版のリンクを一度ずつ開く）。
- Safari は、しばらく開かないサイトの保存内容を消すことがあります。毎日使う本部の端末は、ホーム画面に追加したアプリで使うと消えにくくなります。
- 本部の端末を配布用に回すときは、ブラウザの設定でこのサイトのデータを消してから配布版のリンクを開きます。

**配布版の発行**
1. 本部版で「位置情報共有設定」を開きます。下にある「配布版の発行（本部版だけ）」を使います。
2. 配布先の名前を入れ、制限と期限を選んで「発行する」を押します。期限は、その日の終わりまで有効です。
3. 表示されたリンク・QRコードを、配布先にだけ渡します。この画面を閉じると再表示できません。

**取り消し**：「発行した配布版」の一覧で、取り消し方を選んで押します。どちらも30秒ほどで反映されます。

| ボタン | 配布先で起きること |
| --- | --- |
| 取り消す（データだけ） | 車両の位置・時刻表が見られなくなり、端末に残した時刻表も消える。地図は公開版として使える |
| 取り消して地図も止める | 上に加えて、画面全体が「この配布版は取り消されました」で閉じ、地図も使えなくなる。開き直しても閉じたまま |

- 「データだけ」で取り消した配布版にも、あとから「地図も止める」を付けられます。
- 期限切れの扱いは、発行時の「期限が来たら地図も止める」で決まります。印を付けなければ、データだけ止まります。
- 止めた端末は、新しい有効なリンクを開くと元に戻ります。
- 端末のデータを消すと、キーなしの公開版として地図は使えます。地図は公開されているためで、止めるのは抑止のための仕組みです。車両の位置・時刻表は受信APIで確実に止まります。

**本部版の端末で配布版を確かめる**
- 本部版の端末で配布版のリンクを開く（またはキーを貼り付ける）と、**そのタブだけ**配布版で表示します。上に「配布版を確認中（このタブだけ）」と出ます。
- 本部版のキーは端末に残ります。ほかのタブ・次に開いたときは本部版のままです。
- その配布版を取り消して止めても、止まるのはそのタブだけです。「本部版に戻る」で戻れます。
- 本部版の画面には、左下に「本部統括用」と出ます。

**リンクが途中で崩れたとき**
- アプリやQRの読み取りで、リンクの「?m=senshu」が落ちたり「#」が「%23」に変わったりして届くことがあります。
- キー（#key=…）が付いていれば、本祭支援ツールとして開き直します。

**iPhone でホーム画面に追加して使う場合**
- ホーム画面のアプリは、Safari と保存場所が別です。
- 配布リンクをコピーし、アプリの「位置情報共有設定」→「閲覧キー」で「コピーした配布リンクを貼り付ける」を押してください。

## 黒帯の情報（開錠・施錠・学内施設・イベント・ステージ出演・インフォメーション）とエレベーター（EV）

- **黒帯（画面最上部）**：次の5種類を、本部が決めた順番・回数で流します。
  - 開錠・施錠時間：4号館は420教室、10号館は10101教室が基準です。
    - 文字の色の意味：黄＝施錠が21:00より後、赤＝施錠が22:30を過ぎて翌4:00まで、水色＝開錠が4:00〜6:59
  - 学内施設時間：食堂・セブンイレブンなどの営業時間（休業も表示）
  - イベント時間：屋台（出店グランプリと同じ時間）・LIVE STAGE・Green Stage・フリーマーケットなど
  - ステージ出演：ステージごとの出演の時間（ステージ1つにつき1まとまり）
  - インフォメーション：用意した文や、その場で入れた文
  - 日付で絞る（ON/OFF）：ONのとき、期間中はその日の情報だけを流します。期間外とOFFのときは全日程を順に流します。
  - 長い文は、表示してから左へ流して最後まで見せます。
  - 通信できないときは、前回取得した情報を「前回取得」の印つきで流します。
- **時計の右側**
  - 9号館・10号館のエレベーターの可否：○＝使用可、×＝使用不可の時間帯、ー＝データなし
  - 15秒ごとに7秒間、エレベーターの欄を今日の天気（専修大学周辺：天気・最高/最低気温・降水確率）に入れ替えます（フェードで切り替え。G倉庫INは常に表示）。天気は Open-Meteo（CC BY 4.0）から30分ごとに取得し、取れないときはエレベーターだけを表示します。
  - G倉庫IN：車両が G倉庫に入れるかを表示します。
    - ×：1〜3号車のどれかが、G倉庫の中か外周から8m以内にいる（停車中・走行中とも）
    - ○：近くに車両がいない
    - ー：22時〜6時、または車両の位置を取得していないとき
    - 15分より古い位置は数えません。
- **見られる人**：値は受信APIに置き、閲覧キーを入れた端末だけに表示します。地図は公開されているため、時刻や営業時間はコードに書いていません。
- **高度な設定（情報組込）**：本部版だけ。上部のタブ（「ルート・費用」の右）か、黒帯を押すと開きます。
  - 黒帯の表示：
    - 日付で絞る・期間（空欄なら、情報のある日の最初〜最後）
    - 情報ごとに、流すかどうか・文字の色・1ページの表示秒数
    - 流す順番：種類と回数を並べます。1回＝その情報の全ページを1度ずつ。例：開錠・施錠時間を3回 → イベント時間を1回。
  - 同じ画面の4つのボタン：開錠・施錠時間／学内施設時間／イベント時間／インフォメーション
  - ステージ出演は、「イベント時間」で各ステージの「出演の時間」を開いて入力します。
  - インフォメーションの「今すぐ1回流す」：保存と同時に各端末へ届き（1分以内）、次のページの前に1回はさみます。30分を過ぎたら流しません。
  - 編集中の内容は、保存する前からその端末の黒帯で試せます。保存すると各端末に1分以内に届きます。
  - 配布版のキーでは、時刻表の編集を許可していても、変えられるのはエレベーターの可否だけです（受信APIでも拒否）。
- **エレベーターの編集**：時計を押すと開きます（時刻表の編集を許可したキーだけ）。
  - 「自動」のときは、日ごとに使用不可の時間帯を「10:00-11:30, 14:00-15:00」の形で入れます。
  - 「設定済み」に印のある日は、時間帯の外が○、内が×になります。印のない日はーです。
  - ○・×・ーのボタンを選ぶと、時間帯に関係なくその表示に固定します。
- **保存の決まり（どの画面も同じ）**
  - ほかの端末が先に保存していた場合は保存されません。「変更を取り消す」で最新を読み込み直してから編集してください。
  - 時刻表を読み込むまでは編集できません（「読み込んでいます…」）。変更していなければ保存しません。日を消す保存は、消える日を示して確認します。
- **消してしまったとき**：受信APIのデータベース（D1）は、過去の任意の時点に戻せます（Time Travel。無料プランは7日前まで）。データベース全体が戻るため、その後の配布版の発行・取り消しも戻ります。作業は開発側で行います。

## 構内図（8号館・9号館・10号館）

- 地図で建物を押すと出る詳細に「構内図（各階）を見る」があります。階ごとのタブで切り替え、＋／−で拡大・縮小できます。
- 中身は、大学公式サイト「生田キャンパス」の各号館の配置図（PDF）を、ページごとの画像にして受信APIに置いたものです（閲覧キーで保護。公開リポジトリには置かない）。
- 閲覧キーのない端末では、公式のPDFを直接開きます。
- 大学が配置図を新しくしたら：`tracking-worker/scripts/upload-floor.mjs` の PDF の URL を公式ページのリンクに合わせて直し、`node scripts/upload-floor.mjs prod` を実行します（poppler と webp が必要）。

## 緊急地震速報・地震情報・津波（quake-live.js）

- 機能メニューの「地震情報・緊急地震速報」で切り替えます（既定でON。止めた端末は止めたまま）。ページを開いている間は、更新しなくても即時に受け取ります。
- 緊急地震速報は高度利用者向け（予報・警報）。Wolfx Open API が中継する気象庁の発表を受けます（予備に P2P地震情報 の警報）。地震情報・津波予報は P2P地震情報 から受けます。
- 本祭支援ツール：予測の地域に神奈川県を含む速報（震源が神奈川県のものも）を、黒帯に割り込ませて流します。予報の地域は「震度4以上の予測」の地域だけなので、神奈川県が震度3以下の予測の速報は流れません。地震情報は、神奈川県で震度3以上のときに都道府県をぬり分け、黒帯にも流します。
- ドライブ版：速報はすべて、受けたときだけ最上部に黒帯を出して流します。地震情報は最大震度4以上でぬり分けます（速報がなかった地震はぬり分けだけ）。
- 速報は、その地震の震度の情報が届くまで流し続けます（届かないときは最後の速報から10分で消す）。震度の情報は、最大震度4までは3分、5弱・5強は10分、6弱以上は1時間出します。津波注意報・警報・大津波警報が出ていれば、黒帯の2行目に並べます。
- P2P地震情報の即時接続は同じIPアドレスから2本までです。本部のWi-Fiなどで多くの端末がつながる場合、3台目以降は20秒ごとの取り寄せになります（速報は Wolfx から即時に受けるので遅れません）。
- どれも参考です。避難や行動は、気象庁・自治体の発表と現地の指示に従ってください。

## 当日の開始

1. 車両と端末の対応を決め、記録します（1号車＝どの端末か）。
2. 各車両のスマホで、次を行います。
   - 充電ケーブルをつなぐ
   - Traccar Client を開き、「継続追跡」を ON にする
   - 画面をロックする（アプリをスワイプで終了しない）
3. 本部で、次を行います。
   - 本部版の端末は、初回だけ設定シートの「本部版のリンク」を開く（以後は自動で本部版になる）
   - 配布版の端末は、配布されたリンクを開くだけで使える（キーは端末に記憶される）
4. 一覧で3台を確認します。
   - 「測位 ○秒前」が出ている
   - 誤差（±m）が構内の道路・出入口を見分けられる程度
5. 運転する人が端末を持って車を降りる場合の扱いを決めます。降りると人の位置を表示することになります。

閲覧キーは端末に記憶されます。ブラウザを閉じても入れ直す必要はありません。

## 表示の読み方

| 表示 | 意味 |
| --- | --- |
| 測位 ○秒前 | 端末が測位した時刻からの経過（サーバー時刻で補正済み） |
| 位置がやや古い（30秒超） | 注意。走行中なら送信が遅れている |
| 位置が古い（120秒超・灰色の印） | 停車中か、送信が止まっている |
| 通信あり・停車中の可能性 | 位置は古いが、端末からの通信は続いている |
| 地図に非表示（15分超） | 印は消すが、一覧には最終時刻を残す |
| 未測位・通信あり | 端末はつながっているが、まだ位置が取れていない |
| 本部の受信エラー | 本部の端末が受信APIから取れていない。車両側の問題とは限らない |

## 位置が出ない・止まったとき

1. **本部側**：一覧の下の「本部の受信」を見ます。
   - エラーなら、本部の端末の通信を確認します。
   - 「閲覧キーが違います」なら、閲覧キーを入れ直します。
2. **車両側**：本部側が正常で、特定の車両だけ古い場合は、その端末で次を確認します。
   - 「継続追跡」が ON か
   - 位置情報の権限が「常に」か
   - 電源・回線（機内モード・圏外）
   - Android の電池の最適化
3. **端末のログ**：Traccar Client の「ステータスを表示」を見ます。
   - `Upload response 200`：正常です。
   - `Upload response 403`：送信キーか端末IDが違います。設定シートの QR を読み直します。
   - `Upload response 503`：受信APIの準備中・障害です。端末は自動で再送するので、そのまま待ちます。
   - `Upload error`：回線の問題です。圏外を抜けると、たまった位置を古い順に送ります。地図の位置が戻ることはありません。
4. アプリを強制終了した場合は、もう一度開いて「継続追跡」を ON にします。

## 端末の交代・紛失

```sh
cd tracking-worker
npm run secrets:prod -- --base <受信APIのURL> --rotate vehicle-2   # 2号車の送信キーと端末IDだけ作り直す
```

1. 新しい設定シートの 2号車の QR を、新しい端末で読みます。
2. 旧端末の送信キーは無効になり、旧端末からの送信は 403 で拒否されます。旧端末のアプリは停止します。

閲覧キーが漏れたおそれがある場合は `--rotate view` を実行し、本部の端末で新しい閲覧キーを入れ直します。

## 当日の終了

1. 3台の端末で「継続追跡」を OFF にします。
2. 本部の地図で「停止」を押します。
3. キーをすべて失効させます。

   ```sh
   npm run secrets:prod -- --base <受信APIのURL> --rotate all
   ```

   新しく作られる設定シートは配布しません。

4. 不要な最新位置を消します。

   ```sh
   npx wrangler d1 execute festival-vehicle-tracking --remote --command "UPDATE vehicles_latest SET lat=NULL, lon=NULL, fix_at_ms=NULL, fix_received_at_ms=NULL, last_contact_at_ms=NULL, telemetry_at_ms=NULL, accuracy_m=NULL, speed_kmh=NULL, heading_deg=NULL, battery_pct=NULL, charging=NULL"
   ```

5. Worker と D1 を削除するかは、来年以降に再利用するかで決めます。設定と migration はリポジトリに残っているため、作り直せます。

## 撤回（通常の本祭マップに戻す）

- **地図の表示だけ止める**：本部で「位置情報共有設定」の「停止」を押します。車両の印と一覧が消えます。
- **地図の機能ごと戻す**：`fest-vehicle-tracking.js` を読み込む前の版に戻して push します（GitHub Pages が自動で再公開）。公開前の版のコミットは、リリース時に記録します。
- **受信APIを前の版に戻す**：`npx wrangler deployments list` で版を確認し、`npx wrangler rollback <版ID>` を実行します。

## 無料枠の確認

- 確認場所：Cloudflare のダッシュボード →「Workers & Pages」→ `festival-vehicle-tracking` の Metrics（要求数・エラー・CPU）と、D1 の Metrics（rows read / rows written）。
- 日次枠のリセット：日本時間 9 時。

| 項目 | 無料枠（2026-10-14 時点） | 想定（10秒送信×3台・10秒取得×閲覧5台・12時間） |
| --- | --- | --- |
| Workers 要求 | 10万/日（アカウント全体） | 送信 12,960 ＋ 閲覧 21,600 ＋ プリフライト ≒ 3.5万 |
| D1 書込 | 10万行/日 | 送信1回＝1行 → 約 1.3万行 |
| D1 読取 | 500万行/日 | 閲覧1回＝3行 → 約 6.5万行 |

上限を超えると、その日の受信がエラーになります。半日試験の実測から本祭当日を見積もり、余裕を残してください。送信設定を「最高」精度・間隔0にすると、1台で1秒1回になり、無料枠を超えます。

## ログ

- 受信APIのログに出すのは、車両ID・結果の分類（fix / old / heartbeat / forbidden など）だけです。位置・URL・キーは出しません。URL を自動記録する invocation log は無効にしています。
- `npx wrangler tail` を使う場合は、表示される要求 URL に送信キーが含まれます。画面共有・保存をしないでください。
- 位置の履歴は保存しません。検証の記録は、遅延・件数・エラーの分類を中心にします。
