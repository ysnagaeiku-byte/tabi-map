# 車両の位置（Traccar Client）検証レポート

作成：2026-10-14。実装の範囲は「3台の最新位置のみ」（履歴・新しい地図基盤・自作アプリは含まない）。

## 1. 自動テスト（ローカル・Workers 実行環境＋ローカル D1）

`cd tracking-worker && npm test`：**35件すべて合格**。`npm run typecheck`：エラーなし。

| 区分 | 確認したこと |
| --- | --- |
| POST フォーム / GET 互換 | 現行 Traccar Client と同じ項目の POST を保存。GET クエリでも同じ正規化結果 |
| 単位・境界 | 10 knots → 18.52 km/h／秒とミリ秒の時刻が同じ時刻に／lat=0・lon=0・batt=0 は有効／空文字を 0 にしない／緯度±90・経度±180 |
| 認証・車両の分離 | パスのキーなし・形式違いは 404／別車両のキー・閲覧キーでは書けない（403）／登録外の端末IDは拒否（通信時刻も進めない）／先頭ゼロの端末IDを数値化しない／送信キーでは閲覧できない（401）／閲覧応答に端末ID・ハッシュ・キーを含めない |
| heartbeat | 座標なしは 2xx。通信時刻と電池だけ進み、位置と測位時刻は変わらない |
| 逆順・重複・同時到着 | 200→100→200→300 で最後は 300／古い再送で位置・電池が戻らない／9件同時でも最新の fix が残る |
| 不正値・未来時刻 | NaN・片方欠落・範囲外・120秒超の未来・時刻なしは保存せず `200 accepted:false`（再送キューを詰まらせない）。通信時刻も進めない／設定用 QR をブラウザで開いただけでは何も変わらない |
| 形式 | JSON は 415／8KB 超は 413（Content-Length なしの流し込みも読み取り量で止める）／PUT は 405 |
| 設定不足・DB 障害 | Secret 未設定・形式不正は 503／DB 障害は 503 で成功を返さず、復旧後の再送で保存 |
| 閲覧・CORS | 許可 Origin のプリフライトは 204（DB を読まない）／許可外・`null`・パス付き Origin には CORS を返さない／認証失敗も CORS 付きで読める／全応答 `no-store, private`／`/health` は `{"ok":true}` のみ／`serverNowMs` を返す |
| 入口ファイル | Workers の入口は既定の書き出しだけ（定数を書き出すと実行環境が起動しないことを wrangler dev で確認したため） |

テストの有効性は、わざとコードを壊して確かめました。4種類とも該当のテストが不合格になります。
- 位置を常に上書きする
- Origin を確認しない
- 通信時刻を MAX で更新しない
- 破棄を 400 にする

## 2. ローカル結合（wrangler dev ＋ curl）

`sh scripts/smoke-local.sh`（ダミー値）の結果：

| 要求 | 結果 |
| --- | --- |
| `/health` | 200 |
| 位置（POST フォーム） | 200 |
| heartbeat | 200 |
| 古い再送 | 200（位置は戻らない） |
| 別の端末ID | 403 |
| 閲覧キーなし | 401 |
| 許可 Origin のプリフライト | 204 |
| 許可外 Origin のプリフライト | 403 |

閲覧結果：速度 18.52 km/h、誤差 8 m。heartbeat の電池 55% が反映されることも確認しました。Worker の独自ログは、車両ID・結果の分類だけです（例：`{"route":"ingest","vehicle":"vehicle-1","result":"fix"}`）。

## 3. 地図（本祭支援ツール）の確認

地図ページの確認は、Google Maps を模擬部品に置き換えた検証用ページで行いました。地図 API キーを使わずに動かすためです。受信APIはローカルの wrangler dev を使っています。

| 確認 | 結果 |
| --- | --- |
| 3台の固定一覧 | 1号車「測位 8秒前・15km/h・誤差±6m・電池81%・充電中」／2号車「位置がやや古い・1分前」／3号車「未測位・通信 7秒前・電池90%」 |
| 古さの段階 | 30秒超＝やや古い、120秒超＝古い（灰色の印・「通信あり・停車中の可能性」）、15分超＝印を消して一覧に「地図に非表示」 |
| 移動 | 新しい位置へなめらかに移る（速度での先読みはしない） |
| 地図の切り替え | 標準 → 白地図 → 3D（高低差の印）→ 標準で、位置・色・名前が保たれ、旧マーカーが残らない |
| 画面が裏 | 取得を休み（11秒間取得なし）、表示に戻るとすぐ取得 |
| 通信失敗 | 「本部の受信エラー：通信できません・○秒後に再試行」。再試行は 10 → 20 秒と延び、車両の一覧と印は残る。回線が戻ればすぐ取得 |
| 503 | 「受信APIが準備中です」で再試行 |
| 閲覧キー違い（401） | 「閲覧キーが違います」で再試行を止める（11秒待っても再取得なし） |
| 停止 | Traccar の印と一覧を消し、旧方式（合言葉）の画面を戻す。旧設定があれば再接続（公開ブローカーへの接続部分は無効化して確認） |
| 再読み込み・キーなし | 「閲覧キーを入力してください」。旧方式へは自動接続しない。保存済みの旧設定は消さない |
| 通常版 | `index-google.html`（`?m=senshu` なし）では読み込み・通信なし |
| スマホ幅 375px | 横はみ出しなし |

## 5. 無料枠の推計

| 条件 | Workers 要求/日 | D1 書込/日 | 判定 |
| --- | --- | --- | --- |
| 10秒送信×3台＋10秒取得×閲覧5台、12時間 | 約 3.5万 | 約 1.3万行 | 枠内（10万/10万行） |
| 1秒送信×3台、12時間 | 送信だけで 12.96万 | 12.96万行 | 枠を超える |

送信設定の既定（設定シートの QR）は、精度「高」・間隔10秒・距離0・静止状態の検出 OFF です。これは公式ソースから見た出発点で、実機の送信数と遅延で調整します。

## 6. 仕様の確認先（公式ソース）

- 送信形式（POST フォーム・`timestamp` は秒・`speed` は knots・`batt`・`charge`）：traccar-client-sdk `HttpUploader.kt`
- 再送（先頭が 2xx になるまで後続を送らない・5秒〜5分で再試行）：`TrackerEngine.kt`
- 間引き（間隔・距離・角度のどれかで送る）：`LocationFilter.kt`
- iPhone の位置取得（常時更新・距離フィルタなし）：`IosLocationSource.kt`
- QR 設定の読み込み（URL の origin＋path をサーバーURL、クエリを設定値に）：traccar-client `configuration_service.dart`
- 設定画面の表示条件（iPhone の精度「高」では間隔欄なし）：`settings_screen.dart`
